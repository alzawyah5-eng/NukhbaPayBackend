## Composition and configuration

`@nukhbapay/admin-web/auth0` exports `Auth0Login`. Trusted server composition supplies its configuration and the existing `TrustedStaffActorBoundary` / `StaffSessionLifecycle`, then supplies the same lifecycle and login object to `createStaffPortal`. These are internal dependencies, not environment-selected or browser-created actors. `pnpm.cmd staff:build` builds dependencies; `pnpm.cmd staff:typecheck` checks the BFF. `pnpm.cmd staff:test` builds dependencies and runs synthetic authentication and pinned-localhost HTTPS tests. HTTPS tests require the existing `NUKHBAPAY_STAFF_TEST_PFX_PATH`, `NUKHBAPAY_STAFF_TEST_CA_PATH` and process-only `NUKHBAPAY_STAFF_TEST_PASSPHRASE`; absence fails the suite. Never disable TLS verification.

Required before separately approved activation:

- Exact canonical HTTPS issuer, confidential web client ID and server-only client secret (at least 32 characters). Issuer has a root path and no credentials, port, query or fragment. Token/JWKS endpoints are fixed relative to it; request data and JWT headers cannot select them.
- Register exactly `https://localhost:3001/auth/callback` and `https://localhost:3001/auth/logged-out` as the application's allowed callback/logout URLs. No wildcards, dynamic return paths or proxy-derived origins. Callback origin must match the actual TLS listener. Tests use an ephemeral localhost port.
- Exact staff API audience (reported development identifier `https://api.dev.nukhbapay.com/staff` remains unverified), namespaced signed human-principal claim and approved client. The existing `rfc9068-staff-v1` contract requires RS256, `typ=at+jwt`, `client_id`, `jti` and principal kind `human`; delegated/machine profiles deny. This BFF requires a single exact audience, access-token lifetime at most 300 seconds and no refresh tokens. Demonstrate actual provider emission, including whether Auth0 emits an additional userinfo audience, before activation.
- Demonstrate signed ID-token `typ=JWT`, exact issuer/client audience, matching subject, nonce, `amr` containing `mfa`, and `auth_time` within 300 seconds. Missing, stale or unexpected assurance denies login. `prompt=login` and `max_age=0` request fresh authentication. Confirm actual factor/recovery semantics and emission with the owner; reported Always MFA or token issue time alone is insufficient. This admits only a basic staff session; phishing resistance and privileged action assurance are not claimed.
- Server-selected tenant UUID, pre-enrolled exact issuer/subject identity, active staff/membership and current self-read authorization. No email linking, enrollment, role claim, tenant query parameter or platform inheritance. Configure `TrustedStaffActorBoundary.sessionIssuers` with the exact reviewed issuer; its default remains synthetic-only and an explicit empty list denies all session issuers. Supply current restricted IAM/audit ports and the reviewed session store separately. No deployment is wired here.
- Browser-trusted localhost HTTPS, process-only secret injection, approved persistent session target, owner-approved residency, egress, rate limits/monitoring and retention/recovery/HA remain separate operational gates. No real-provider or persistent-database acceptance was performed.

## Security behavior

GET `/auth/login` creates independent random 256-bit state, nonce, transaction cookie and PKCE verifier; only S256 is used. The server retains the verifier and any previous session credential. The transaction cookie is host-only Secure, HttpOnly, Path=/, SameSite=Lax, with a 300-second lifetime, so a cross-site GET callback carries it. The staff session remains SameSite=Strict. Starting another login cancels the supplied prior transaction. Transactions are process-local, capped at 1000 including in-flight callbacks, expire after five minutes and fail closed across restart. Shutdown invalidates them.

Only the exact GET `/auth/callback?...` and public GET `/auth/logged-out` landing permit provider cross-site navigation. Host/duplicate-header checks, strict cookie parsing and other origin checks remain in force. Callback code/state are single-valued and bounded; unknown parameters, provider errors, wrong issuer hints and replay deny. Transactions are consumed synchronously before any await, including on exchange/verification failure; no automatic retry occurs. State/nonce use constant-time comparison. Errors return fixed text without provider responses, claims, codes or causes; responses are no-store and no-referrer.

The backend exchanges the code with the exact callback, verifier and confidential client credentials over verified HTTPS. Redirects, ambient credentials and caching are disabled. Token/JWKS responses have byte limits and three-second deadlines covering body streaming. `jose` verifies signatures using only fixed-issuer public RSA keys of 2048–4096 bits. JWT key pointers and private JWKS material deny. ID/access token types, issuer, audience, client, times and subject are checked separately; `at_hash` is checked when present. Tokens are transient server-side values, never browser storage, response JSON, session records or logs.

After token/assurance verification, the actor boundary resolves exact trusted identity and tenant authority. The session lifecycle issues or rotates an opaque credential with hash-only storage, committed audit, fresh authority/version/grant checks, idle/absolute/identity expiry and revocation. Session expiry is additionally bounded by verified authentication time plus five minutes. Reauthentication rotates the server-captured previous credential even though Strict cookies are absent on the callback. Identity/tenant switching during rotation denies; sign out first. Existing actor/session results retain `NOT_AUTHORIZED` and `assurance=not-established` for privileged operations. No reserved permission or APPLY path opens.

POST `/auth/logout` requires exact origin, session-bound CSRF token and empty JSON. It confirms audited local revocation before clearing cookies or returning the fixed Auth0 `/v2/logout` URL with public client ID and fixed allowed return URL. The browser script navigates there; the API does not fetch it. Provider/federated logout is not claimed by local success. Revocation failure reports unavailable and never claims logout. Pending/in-flight callbacks are cancelled; cancellation racing a committed session withholds the credential and attempts revocation. Failed cleanup can leave an undisclosed, expiring server record, never an issued browser credential.

## Test scope

Synthetic RSA-signed tokens, mocked Auth0 token/JWKS responses and a one-use in-memory ticket store exercise the actual actor/session lifecycle. Tests cover PKCE, state/cookie/nonce/issuer/client/audience/subject/profile/assurance failures, replay/concurrent callbacks, response limits, staff/membership/authority changes, audit/store failures, rotation, logout and shutdown races. Pinned localhost HTTPS tests cover redirects/cookies/headers and CSRF. No real Auth0 or persistent database is contacted. Application session tests cover idle/absolute expiry and opaque actor/ticket forgery; an added test proves explicit issuer allowlisting.

References: [OAuth security best current practice](https://www.rfc-editor.org/rfc/rfc9700.html), [Auth0 ID-token validation](https://auth0.com/docs/secure/tokens/id-tokens/validate-id-tokens), and [Auth0 logout redirect contract](https://auth0.com/docs/authenticate/login/logout/redirect-users-after-logout).
