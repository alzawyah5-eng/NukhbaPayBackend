# Catalogue refresh lifecycle (source and offline qualification)

The existing ScheduledCatalogRefresh coordinator owns import replay and exact draft recalculation. CatalogueRefreshHost adds explicit start, stop, restart and bounded polling. createCatalogueRefreshStore is a PostgreSQL adapter for separately supplied approved workload pools and a fixed tenant allowlist. Construction opens no connection. No timer, environment startup, credential lookup or provider account is enabled by this increment.

Configure dailyRefreshSchedule with a UTC minute 0..1439. Persist schedule id, tenant/account, explicit provider/source/version and enabled flag. A daily interval is exactly 86,400,000 ms. Owner must define local-time/daylight-saving policy before runtime. Schedule changes require a new version. Runtime configuration writer/approval is not implemented. Proposal 012 is unregistered and unapplied; it must be reviewed separately from R6.

An explicit trusted composition injects the approved store and the existing synthetic coordinator into CatalogueRefreshHost. options: concurrency 1..4, pollMs 10..60000, timeoutMs 10..60000, leaseMs at least timeout+1000 and at most300000, ownsStore true only when this host owns the store. Configure an approved pg pool with max at most4, bounded connect/query timeouts and no excess grants before acceptance. Start once; await stop before disposing/restarting. stop aborts and joins work before closing an owned store. A provider that ignores AbortSignal must still be joined; hard process containment and cold/soak acceptance remain pending. No unjoined Promise.race timeout is used.

Claims, state transitions and audit insertions commit atomically on the same checked-out connection. Schedule row locks with SKIP LOCKED prevent duplicate slot reservation across hosts. Job key is tenant/schedule/version/slot; fenced token and unexpired lease are required to settle. The coordinator pins version and slot and derives the same import and draft idempotency keys on retry. Existing per-account admission also rejects overlap. No publication port is supplied.

Only a provider read failure before any import or draft write may become RETRY_WAIT. Maximum three attempts, backoff 1s then2s. All ambiguous import/save/commit failures and cancellation become UNCERTAIN; expired CLAIMED jobs become UNCERTAIN with LEASE_EXPIRED. Uncertain jobs block new work for that schedule. There is no automatic lease takeover or retry of uncertain work. Owner reconciliation must check the exact job token, snapshot and draft receipts under fresh authorization; the reconciliation mutation adapter is intentionally pending. FAILED jobs retain evidence and may only receive a new daily slot under the approved schedule.

Diagnostic data is bounded state/reason/attempt/time, never raw upstream errors or credentials. Approved operators may inspect jobs and audit evidence using a separately reviewed reader; no public job-status endpoint exists. close releases only owned pools. Transaction errors roll back, and failed rollback or uncertain COMMIT discards the client exactly once.

Offline tests use controlled client transcripts and durable-state doubles across host instances. They do not prove PostgreSQL locking/RLS, process restart, cold-start timing or long-running stability. Required runtime qualification: reviewed012 schema and least-privilege matrix, transaction/audit failure injection, two independent processes claiming the same slot, process kill at read/import/draft/commit boundaries, fenced stale settlement, cancellation/connection disappearance, next-day schedule behavior, soak and source-freshness checks. Never run these with real payment operations or deployment credentials.
